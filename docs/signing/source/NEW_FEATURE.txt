Описание процесса:
Наш процесс это предоставление пользователю возможность подписать документы для любого потребителя в виде систем банка.

При вызове нашей системы пользователь получает смс с ссылкой на этот развернутый фронтенд

После перехода по ссылке, пользователь запусает фронтенд и у нашего процесса есть несколько "process" - так мы называем статусы заявки на подписание.

1. START - ему соотвествует экран START, на этом этапе нам нужно получить "inquiry_id", который находится внутри квери параметров, пример:

https://digital-id.sandbox.digital.gov.ru/sign?id=123asd123 - 123asd123 и будет "inquiry_id"

Получение айди находится в useInquiryId.ts

После получения id фронтенд должен вызвать запрос getSettings с ключом settings и получить ответ
Если ответ по этому запросу не 200 ок или не проходит валидацию схемы ответа задать значения по умолчанию и сохранить в контексте react
retry_time	Время, через которое надо сделать ретрай (в мс) = 1000
retry_addition	Время, до которого рандомим	= 200
retry_count	Максимальное количество ретраев на экран = 3
pull_time	Время, через которое надо сделать пуллинг (в мс) = 10000

После получения настроек мы должны вызвать запрос state с событием start
Дождаться ответ и если ответ 200 ок провалидировать его по схеме ответа: может вернуться json с процессом, а может с task в зависимости от этого могут отличаться действия.
При получении json с процессом нужно переключить экран с помощью внутреннего роутинга на определенный экран связанный с этим процессом и выполнить требования на нем. Экраны зависят от процесса, о них далее.
А ответ сохранить в контексте react.

Далее описываются альтернативные сценарии при вызове state с событием start:
Альтернативный сценарий 1	Ответ REST.01 содержит HTTP-код 503
Фронт переходит к экрану STATUS с кодом ошибки SERVICE_UNAVAL (см. Справочник ошибок)

Альтернативный сценарий 2	Ответ REST.01 содержит HTTP-код 401
Фронт переходит переходит к сценарию "Старт процесса" и НЕ заполняет айдишник сессии, даже если оне есть.

Альтернативный сценарий 3	Ответ REST.01 содержит HTTP-код 403
Фронт переходит к экрану STATUS с кодом ошибки SERVICE_UNAVAL (см. Справочник ошибок)

Альтернативный сценарий 4	Ответ REST.01 содержит HTTP-код 400, 500
Фронт переходит к экрану STATUS с кодом ошибки RESPONSE_ERROR (см. Справочник ошибок)

Альтернативный сценарий 5	Ответ REST.01 содержит HTTP-код 429, 504
Фронт делает ещё попытку через retry_time + рандомно от 1 до retry_addition мс , если попытки ещё есть.
Всего retry_count попыток.
Если попыток больше нет, то фронт переходит к экрану STATUS с кодом ошибки RESPONSE_ERROR (см. Справочник ошибок)

Альтернативный сценарий 6	Тайм-аут
Фронт делает ещё попытку через retry_time + рандомно от 1 до retry_addition мс, если попытки ещё есть.
Всего retry_count попыток.
Если попыток больше нет, то фронт переходит к экрану STATUS с кодом ошибки RESPONSE_ERROR (см. Справочник ошибок)

2. Процесс SETTING ему соответсвует экран Setting
На этом процессе мы проверяем настроено ли рабочее место у пользователя, в частности:
Установлено ли расширение CRYPTO PRO
Установлено ли и настроено CryptoPro CSP
Сейчас весь код связанный с крипто про находится в файле CryptoService
Этот код взят из других проектов поэтому использовать его можно только как подсказку.
ЖЕЛАТЕЛЬНО:
При работе с крипто про использовать библиотеку https://github.com/Humble-saaber/crypto-pro-actual-cades-plugin - если это не возможно использовать execute который поставляется в этой библиотеке.

Перед проверкой мы должны проверить сохранено ли в локальном хранилище информация о том проходило ли проверку текущее рабочее место в последнии 24 часа успешно проверку
Если рабочее место проходило проверку, тогда саму проверку мы можем пропустить и вызвать state с event ready
Иначе же пройти проверку.

Если айди внутри локального хранлища не совпадает с айди пришедшего с запросом, то считать проверку провальной

Сохраняем в локальном хралилище под ключем digital_id_sign минимум:
id заявки - inquiry_id, а не session, даже если где-то указано иначе ВАЖНО!!!
Время прохождения настройки
Устройство, на котором проходили настройку

1.Настроен ли браузер - расширение и запустился ли cades plugin api в window
