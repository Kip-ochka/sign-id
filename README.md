# SIGNING

Веб-приложение для подписания документов по ссылке из SMS. Стек проекта — React 17, TypeScript и Vite. Требования, API и статус приёмки описаны в [документации SIGNING](docs/signing/README.md).

Требуется Node.js 20.19+ в ветке 20, 22.13+ в ветке 22 или 24 и выше.

## Разработка

```sh
npm ci
npm run dev
```

Vite запускает фронтенд. Приложение считывает `id` из SMS-ссылки и обращается к API по относительным путям `/proxy/services/…`. В dev эти запросы проксируются на локальный мок (порт 3001). Для подписания на рабочем месте нужны Browser Plug-in, КриптоПро CSP и действующий сертификат.

## Моковый бэкенд

В двух терминалах запустите `npm run mock` и `npm run dev`, затем откройте [приложение с тестовой заявкой](http://localhost:5173/?id=mock-inquiry).

Все данные и переключатели находятся в корневом [mock-data.mjs](mock-data.mjs):

```js
state: {
  start: 'SETTING',
  ready: 'CHECK',
  check: 'SIGNING',
  signing: 'STATUS_SUCCESS',
},
poll: 'STATUS_SUCCESS',
```

Для любого события выберите ключ из объекта `process` или отредактируйте сам ответ. Сохранение файла перезапускает Node через `--watch`; следующий запрос получит новые данные. Чтобы сразу открыть нужный процесс, поменяйте `config.state.start` и перезагрузите страницу. Учтите: действующий клиентский кэш SETTING может сразу отправить ready; для ручной проверки SETTING удалите `digital_id_sign` из localStorage.

Готовые кейсы: SETTING (в том числе SETTING_EMPTY), CHECK, SIGNING с двумя документами и SIGNING_SINGLE с одним; STATUS_SUCCESS, STATUS_WARNING, STATUS_ERROR, STATUS_TIMER (внешний переход через 5000 мс), TASK, INVALID_RESPONSE; CHECK/SIGNING с суффиксами BATCH, ARCHIVED, XML, ATTACHED для проверки fallback вне MVP. Хэши синтетические, не подтверждают криптографическую целостность файла.

Для ожидания выберите `TASK` в нужном событии. `config.poll` задаёт постоянный ответ `/poll/status`: TASK продолжает ожидание, любой процесс завершает его. Никаких счётчиков и автоматической смены ответов нет. HTTP-статусы меняются отдельно в `config.http`: можно поставить 400, 401, 403, 429, 500, 503, 504; для 303 задайте TASK в событии (ответ без Location). Такой статус будет возвращаться на каждый запрос, включая retry/restart.

`/document` всегда отдаёт одинаковый текстовый файл в `multipart/mixed`, подставляя `document_id` из JSON запроса. `/settings` всегда отдаёт `settings`, остальные ключи справочника — постоянный `errorScreen`. Multipart check/signing принимается без проверки подписей. Сервер слушает только `127.0.0.1:3001`; другой порт задаётся переменной `MOCK_PORT` в обоих терминалах. Прокси настроен только для dev, production-сборка использует прежние относительные маршруты.

## Границы MVP

CHECK подписывает один тестовый документ. SIGNING последовательно подписывает документы группы одним сертификатом в режиме `single/other/detached` с профилем PKCS#7 и отправляет полный комплект. Для остальных режимов приложение показывает локальный STATUS. Требования к CryptoPro и условия внешней приёмки описаны в [криптографическом контракте](docs/signing/CRYPTO_CONTRACT.md).

## Проверки и форматирование

| Команда                | Назначение               |
| ---------------------- | ------------------------ |
| `npm test`             | Запустить тесты Jest     |
| `npm run typecheck`    | Проверить типы           |
| `npm run lint`         | Запустить ESLint         |
| `npm run format:check` | Проверить форматирование |
| `npm run format`       | Отформатировать файлы    |

Для отдельной автоматической проверки обработки HTTP 303 нужен Chromium. Скрипт сам поднимает временный HTTP-сервер на loopback. Команда и протокол приведены в [контракте API](docs/signing/API_CONTRACT.md#проверка-ac-22).

## Сборка

```sh
npm run build
npm run preview
```

Команда `build` проверяет типы перед сборкой. Готовая сборка находится в `dist/`. Команда `preview` запускает её локальный предпросмотр.

## Предпросмотр актуального дизайна

Компоненты из `actual-design` перенесены в рабочий src. Внутренние UI-kit заменены локальными реализациями с сохранением имён импортов; [границы совместимости](src/shared/vendor/README.md). Закрытые пакеты для локальной сборки не нужны.

После npm run dev откройте [галерею экранов](http://localhost:5173/test/design-preview.html). Она использует синтетические данные, поддерживает выбор сертификата и открытие тестового документа, не отправляет запросы API и не создаёт криптографические подписи. Это отдельная dev-страница; в production-сборку и пользовательскую навигацию она не входит. Основной вход приложения по-прежнему использует id из SMS-ссылки и действующий сценарий.
