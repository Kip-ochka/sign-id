# 07. Список, просмотр и скачивание документов

Статус: не начата. Зависимость: 06. Результат — просмотр документов SIGNING до основного подписания.

## Вход

R-18/R-19, [API](../API_CONTRACT.md), [UI](../UI_SPEC.md), `getDocument`, `parseDocumentResponse`, существующие тесты документа.

## Работа

1. Подключить данные SIGNING к экрану: title/message, optional step, список документов с id/title/format. Данные нового ответа заменяют предыдущую группу документов.
2. По пользовательскому действию вызвать REST.03 с inquiry_id и выбранным document_id. Не скачивать все документы заранее без требования.
3. Проверить multipart и метаданные, пригодность Base64 и совпадение id. Ошибки HTTP не смешивать с ошибкой декодирования; обе приводят к правильному статусу операции.
4. Составить Blob с согласованным типом файла. Поддержанный браузером документ открыть выбранным в задаче 03 способом, неподдержанный скачать с безопасным именем. Предусмотреть ручное скачивание при отказе просмотра.
5. Сохранить рабочий экран SIGNING/выбор при закрытии просмотра. Не встраивать потенциально исполняемый контент в DOM приложения.
6. Управлять object URL и ресурсами: освобождение при закрытии/замене/unmount, без преждевременного revoke. Повторный клик одной строки не дублирует загрузку; ответ предыдущей заявки не открывается поверх новой.
7. Применить отдельные ошибки REST.03: 503 → SERVICE_UNAVAL; 403/400/500/ошибка тела → RESPONSE_DOC_DOWNLOAD_ERROR; первый 401 → START, повторный → RESPONSE_ERROR; временные ошибки → максимум `max(1, retry_count)` вызовов на загрузку. BACK после ошибки возвращает к списку, не подписывает.

## Не входит

Само подписание, серверная генерация документов, новый backend endpoint и изменение формата ответа на JSON.

## Приёмка

AC-15–AC-17, AC-26/AC-27. Проверить валидный PDF/поддержанный формат, неизвестный формат, отказ просмотра, отсутствие частей, битый JSON/Base64, несовпадение id, HTTP-матрицу и очистку ресурсов. Сохранить существующие multipart-тесты.

Результат скачивания и возврат к SIGNING проверить в браузере. Typecheck, целевые API/сценарные тесты, lint и build.
