# 05. Настройка рабочего места и кэш 24 часа

Статус: не начата. Зависимость: 04; использует сценарий 02 и UI 03. Результат — полный SETTING и безопасный пропуск повторной проверки.

## Вход

R-09–R-13 из [требований](../REQUIREMENTS.md), [CryptoPro](../CRYPTO_CONTRACT.md), Q-05 и D-07 из [решений](../DECISIONS.md).

## Работа

1. Определить запись `digital_id_sign`: inquiry_id из валидного query `id`, время успешной проверки, устройство по Q-05. Вход без id завершается локальным STATUS до проверки кэша. Допустимо поле версии записи для контролируемой миграции.
2. Валидировать чтение и TTL. Повреждение, чужая заявка, другое устройство, будущая дата, возраст >= 24 ч или недоступность storage — промах. Не использовать `digitalid_sign_inq` как замену этому кэшу.
3. Подключить guard SETTING в общий диспетчер ответа до изменения отображаемого экрана. При cache hit сохранить новый ответ/нужные данные процесса, оставить предыдущий экран с блокировкой действий и вызвать ready один раз. При ошибке ready использовать общую сетевую политику, не повторять проверку автоматически.
4. При cache miss показать SETTING и ждать кнопки. Проверять extension → program → certificate последовательно; тексты брать по `name` из screen, не по позиции в массиве. Неизвестные/отсутствующие имена согласовать в рамках Q-14, не выдавать успех без трёх обязательных проверок.
5. Ошибка помечает соответствующий этап, остальные остаются непроверенными. «Подробнее» открывает STATUS по коду; пустая выборка — NO_CERT. BACK возвращает к настройке с возможностью повторить проверку.
6. Только после полного успеха сохранить кэш, список сертификатов в памяти и отправить ready. Отказ записи storage не отменяет фактический успех текущей проверки; просто не даёт будущего cache hit (D-07).
7. Повторный клик/вход не создаёт параллельные проверки или ready. После смены заявки старый результат не записывается как успех новой заявки.

## Не входит

Тестовое и основное подписание, установка CSP и сертификатов, выдача фиктивного успеха на основании одного факта наличия расширения.

## Приёмка

AC-02, AC-07–AC-10, AC-26. Тесты времени на границе 24 ч; cache hit из START и другого рабочего экрана; нет даже промежуточного отображения SETTING; no-cert/detail/BACK; запрет localStorage; двойной клик; поздний ответ старой заявки.

В успешном пути ready отправлен ровно один раз. При cache hit CHECK/SIGNING впоследствии всё равно заново ищут сертификаты. Typecheck, целевые тесты и проверка UI.

## Передача

Обновить PROGRESS: формат локальной записи, идентификация устройства, очистка/миграция, доказательства guard без мигания.
