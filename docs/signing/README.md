# Постановка: подписание документов SIGNING

Пакет требований и задач подготовлен 13.11.2026. Команды запуска приведены в [README проекта](../../README.md), текущие результаты реализации и приёмки — в [PROGRESS.md](PROGRESS.md).

Цель: пользователь открывает ссылку из SMS, проверяет рабочее место, подтверждает владение сертификатом тестовой подписью и подписывает документы банковской системы. Следующий бизнес-процесс определяет бэкенд.

Интеграционный стенд недоступен для задач пакета. Реализация опирается на требования и подтверждённые решения. Приёмка использует синтетические данные, а браузерные HTTP-сценарии проверяются с локальным бэкендом. [Решение пользователя](DECISIONS.md#граница-приёмки-без-стенда).

## Как поставить задачу LLM

> Прочитай AGENTS.md, docs/signing/README.md и docs/signing/PROGRESS.md. Выполни задачу docs/signing/tasks/NN-name.md в её границах. Обязательные входные документы перечислены в задаче. Различай требования R-_, рабочие решения D-_ и вопросы Q-_. Не выдумывай ответы на Q-_. Проверь критерии AC-* и обнови PROGRESS.md. Не переходи к следующей задаче без запроса, если пользователь поручил только одну.

## Происхождение и приоритет

1. Прямой запрос пользователя: только аналитика сейчас; простой интерфейс нужно спроектировать отдельной задачей; state-навигация, CSS Modules, очистка CryptoPro.
2. `source/NEW_FEATURE.txt`: неизменённая копия `C:/Users/Kipo/Downloads/ТЕКСТ/NEW_FEATURE.txt`. SHA-256: `E02979EB5BE32155F31D10BFC13DD43C7B3A28004AA8A78857AD1106742D11FB`. Номера строк в матрице приёмки относятся к этой копии.
3. Существующие код, схемы API, `ERRORS_REFERENCE.md`, `API_TESTING.md`: данные для сопоставления с требованиями, не автоматическое подтверждение спорного контракта.
4. Предложения аналитика обозначены D-_; они не выдаются за слова заказчика. Противоречия и пробелы обозначены Q-_.

Повторы обработки HTTP объединены в одну матрицу. Опечатка `status с event ready` нормализована в `state('ready')`. Названия процессов сохранены в верхнем регистре, HTTP-события приведены к существующим `start`, `ready`, `check`, `signing`. Номера шагов в альтернативных сценариях исходника местами ошибочны; ошибки привязаны к операции, а не к номеру шага.
