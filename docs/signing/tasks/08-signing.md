# 08. Подписание документов и отправка результата

Статус: завершена. Зависимость: 07. Результат — одиночная отсоединённая подпись MVP. Доказательства приёмки приведены в [PROGRESS.md](../PROGRESS.md).

## Вход

R-18/R-20/R-21, [API](../API_CONTRACT.md), [CryptoPro](../CRYPTO_CONTRACT.md), Q-09/Q-12/Q-14/Q-15.

## Работа

1. При новом SIGNING заново проверить окружение и получить подходящие сертификаты. Применить правила выбора как в CHECK, сбросить устаревший выбор при изменении фильтров/списка.
2. По кнопке создать неизменяемый план операции: заявка, версия текущего ответа, выбранный сертификат, документы, режим, формат/позиция, алгоритм, хэши и TSP. Изменения UI не должны менять уже начатую подпись.
3. Проверить полноту данных до вызова CryptoPro. Неподдержанный алгоритм, отсутствующий нужный хэш и неподтверждённая комбинация дают контролируемый отказ без попытки другим способом.
4. При `single/other/detached` пройти список в порядке ответа. Для каждого документа дождаться завершения той же операции подписи, передав его хэш и тот же выбранный сертификат. Сохранить подпись с id документа и только затем перейти к следующему. При `batch`, `archived`, `xml`, `attached` или неизвестных значениях использовать локальный fallback R-27 без подписи, `getSettings` и `state('signing')`.
5. Проверить результат каждой подписи. При ошибке остановить цикл и передать ошибку общему обработчику. Не отправлять частичный комплект.
6. После N успешных подписей сформировать один `state('signing')` с N документами, N файлами `<document.id>.sig` и метаданными и файлом одного выбранного сертификата.
7. Разделить сетевую отправку и создание подписи. Для разрешённых по Q-12 повторов отправки использовать готовые файлы и бюджет `max(1, retry_count)` вместе с первой отправкой. Формат запроса при повторе следует согласованной политике идемпотентности.
8. Передать ответ общему диспетчеру: повторный SIGNING обновляет документы и параметры; task запускает ожидание; STATUS отражает результат сервера. Не показывать «Документы подписаны» сразу после локального успеха плагина.
9. Проверить блокировку повторных действий, отмену применения старых результатов, BACK без повторной подписи и корректные ошибки CryptoPro/NO_CERT/REST.01.

## Не входит

Batch, archived, XML и attached отложены на следующие версии. Серверная верификация и работа с закрытым ключом вне плагина находятся за пределами задачи.

## Приёмка

AC-10/AC-11/AC-13/AC-18/AC-19/AC-26. Проверить `single/other/detached` для одного и нескольких документов, соответствие id и хэшей, строго последовательные вызовы с одним сертификатом и одну отправку после полного успеха. При сбое на втором из трёх документов третий не подписывается и отправки нет. Проверить fallback для каждого неподдерживаемого режима. Проверить 256/512, TSP/profile, исчезнувший токен, несколько групп SIGNING и устаревший ответ. По Q-12 проверить повтор отправки после HTTP 429/504 с готовыми файлами и `RESPONSE_ERROR` после локального таймаута без автоматического повтора.

Typecheck, целевые тесты, lint и build. Проверить формирование и отправку полного комплекта на синтетических данных. Если часть Q-* блокирует обязательный критерий, записать блокировку и продолжить независимую работу.
