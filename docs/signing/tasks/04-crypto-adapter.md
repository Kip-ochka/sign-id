# 04. Переработать и очистить слой КриптоПро

Статус — завершена в границах работы агентов. Реализация и проверки адаптера описаны в [CRYPTO_CONTRACT.md](../CRYPTO_CONTRACT.md#реализация-задачи-04). Зависимости 01–03.

## Вход

[CRYPTO_CONTRACT.md](../CRYPTO_CONTRACT.md), [контекст](../PROJECT_CONTEXT.md), R-03/R-11–R-15/R-17/R-20, Q-05/Q-09/Q-14/Q-15. Прочитать существующий `src/shared/services/CriptoPro` и API установленной библиотеки.

## Работа

1. Найти статические, динамические и глобальные использования старых функций. Зафиксировать для каждой группы «заменить / сохранить с причиной / удалить». Отдельно учесть побочные эффекты и регистрацию callback плагина.
2. Создать операции адаптера: проверка браузера/плагина, CSP, поиск сертификатов, разбор реквизитов, экспорт публичного сертификата, определение параметров и подпись. Операции не зависят от React и не открывают экраны.
3. Нормализовать ошибки с сохранением исходного кода и стадии. Не сводить все сбои к старым ER0202/ER0204; данные передавать общему error resolver.
4. Реализовать маппинг OID по спецификации; Subject/Issuer разделены. Отсутствующие реквизиты и фильтрация — по Q-14/Q-15. На неподтверждённую семантику не выдавать видимость полного покрытия.
5. Сверить OID с API сертификата и проверить выбор hash256/hash512 и параметра алгоритма на моках. Передавать готовый хэш и профиль `PKCS7` по Q-09.
6. Использовать API библиотеки и её `execute` для недостающих параметров. В MVP реализовать `single/other/detached` для одного хэша за вызов. Эту операцию CHECK вызывает один раз, а SIGNING последовательно для каждого документа. Цикл и отправка относятся к задаче 08. Любой другой режим вернуть как неподдерживаемый до вызова подписи. Сценарий показывает локальный fallback по R-27.
7. Удалить подтверждённо неиспользуемые генерацию/установку сертификатов, копии cades_api, утилиты контейнеров, старые экспорты, UI/LESS. При замене нужного кода очистить старый путь и импорты в том же этапе.

## Не входит

Создание сертификатов, установка ПО и отправка сетевых событий. Полная очистка всего проекта вне криптослоя не требуется.

## Приёмка

AC-09–AC-11/AC-13/AC-18/AC-28 на уровне адаптера. Минимум: отказ extension, отказ CSP, отсутствие сертификатов, optional filters, отдельный Issuer, выбор 256/512, неподдержанный OID/режим, повреждённый результат подписи. Проверить, что нет скрытого параллельного подписания через старый Promise.all.

Typecheck, lint, целевые тесты, build и поиск оставшихся импортов удалённых модулей. Адаптер и обе ветки ГОСТ 2012 проверяются на синтетических данных.

## Передача

Записать публичные операции адаптера, матрицу поддержки, удалённые части и доказательство отсутствия потребителей. Обновить CRYPTO_CONTRACT/PROGRESS; явно отметить оставшиеся вопросы.
