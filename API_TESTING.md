## Запуск в SIGNING

1. Установите Node.js из ветки **24 LTS**. Команды запускайте из корня проекта, рядом с `package.json`.
2. Проверьте версии и установите зависимости из lock-файла.

   ```sh
   node --version
   npm --version
   npm ci
   ```

3. Запустите весь набор. Для одного файла передайте его путь после `--`.

   ```sh
   npm test
   npm test -- src/shared/api/__tests__/document-response.test.ts
   ```

Тесты запросов открывают свободный TCP-порт на `127.0.0.1` и закрывают его после завершения. Им нужен доступ к loopback. При `EACCES 127.0.0.1` проверьте ограничения песочницы или CI. Рабочий сервер, внешний прокси и учётные данные для тестов не нужны. Тесты используют HTTP-адаптер Axios для Node.js. Браузерный XHR и поведение `303` этот набор не проверяет.

## Перенос в основной TypeScript-проект

1. Перейдите в каталог с `package.json` и используйте Node.js 24 LTS. Установите закреплённые тестовые зависимости.

   ```sh
   npm install --save-dev --save-exact jest@30.3.0 @jest/globals@30.3.0 ts-jest@29.4.5
   ```

   Если TypeScript и типы Node.js уже есть, оставьте версии основного проекта при совместимости с `ts-jest`. Если их ещё нет, установите версии из проверенного набора.

   ```sh
   npm install --save-dev --save-exact typescript@5.9.3 @types/node@22.20.5
   ```

2. Скопируйте `jest.config.js` в корень. В проекте с `"type": "module"` файл работает как есть. Для CommonJS-проекта переименуйте его в `jest.config.cjs` и замените `export default` на `module.exports =`. Если Jest уже настроен, перенесите из файла параметры `testEnvironment`, `testMatch` и `transform` в подходящую конфигурацию Jest.

   Конфигурация ищет файлы `*.test.ts` под `src/` и преобразует их в CommonJS при запуске Jest. Если исходники используют алиасы из `compilerOptions.paths`, добавьте соответствия в `moduleNameMapper`. Если нужен отдельный TypeScript-конфиг, вынесите настройки объекта `tsconfig` из `transform` в `compilerOptions` файла `tsconfig.jest.json`, задайте ему `"extends": "./tsconfig.json"` и укажите `tsconfig: '<rootDir>/tsconfig.jest.json'` в настройках трансформации.

3. Для проекта без тестовой команды добавьте в `scripts` запись `"test": "jest --runInBand"`. Если `test` уже занят, добавьте `"test:api": "jest --runInBand"` и используйте `npm run test:api`.
4. Скопируйте `src/shared/api/__tests__/` рядом с API-слоем. Если его структура отличается, поправьте импорты API, типов и файловых утилит. Сверьте ожидаемые маршруты, JSON и multipart-части с HTTP-контрактом основного проекта. В `requests.test.ts` тестовый экземпляр конфигурации клиента должен направлять запросы на локальный сервер и восстанавливать исходные настройки после тестов.
5. Запустите тесты и проверку типов основного проекта. Добавьте изменённые `package.json`, `package-lock.json`, конфигурацию Jest и тесты в репозиторий. В CI достаточно выполнить `npm ci` и выбранную тестовую команду на Node.js 24 LTS с доступом к loopback.
