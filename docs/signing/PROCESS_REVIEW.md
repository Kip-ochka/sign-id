# Проверка модуля process — 18.11.2026

Проверена текущая рабочая копия, включая существовавшие незакоммиченные изменения. Исходный запрос — аудит всего `src/process/`; дополнительный запрос пользователя — очистка `state.session` по истечении срока. Остальные замечания не исправлялись автоматически.

## Подтверждённая ошибка, требующая исправления

### P2. CHECK пропускает явную проверку окружения

Место: `src/process/useProcess.ts`, `openSignatureScreen`, условие `screen.process === 'SIGNING'`.

`checkBrowserPlugin()` и `checkCsp()` вызываются только для SIGNING. CHECK сразу вызывает `findCertificates()`. Поиск сертификатов обращается к плагину, но не заменяет отдельную проверку расширения/Browser Plug-in и не проверяет CSP 5.0+. Это расходится с R-14, в том числе при прямом ответе START → CHECK и после пропуска SETTING по кэшу.

Временные диагностические тесты с CSP 4.0 и успешным синтетическим поиском сертификатов подтвердили три пути: прямой вход, попадание в кэш SETTING и BACK после NO_CERT. Во всех случаях явные проверки плагина/CSP не вызывались, CHECK позволял создать подпись и отправить `state('check')`. Это проверка клиентского управления вызовами на моках, а не подтверждение работоспособности реального CSP 4.0.

Исправление: выполнять проверки окружения для обоих экранов, сохранять проверки отмены между асинхронными действиями. Добавить отрицательные сценарии CHECK для отказа расширения/плагина и CSP ниже 5.0; пересмотреть существующие ожидания числа вызовов, которые сейчас закрепляют пропуск проверок.

## Исправлено по дополнительному запросу

### Очистка state.session после TTL

До исправления `sessionStorage` удалял истёкшую запись, а HTTP getter переставал передавать Session-id, но Context продолжал хранить прежний `state.session`. Временная диагностическая проверка воспроизвела расхождение после 115 минут.

Теперь хранилище предоставляет валидированную запись со сроком через `readEntry()`. React планирует очистку по оставшемуся сроку и снимает свой таймер при смене сессии или unmount. Новый ответ SETTING перепланирует срок, включая повтор прежнего id. Перед очисткой повторно читается актуальная запись, поэтому продлённая сессия сохраняется. Истечение TTL устанавливает `undefined`; отдельное состояние `null` после 401 сохраняет прежнюю семантику.

Добавлены постоянные регрессии: восстановленная сессия истекает без запросов; новый SETTING заменяет сессию или продлевает прежнюю; при истечении между HTTP-попытками Context тоже очищается. Существующий сценарий unmount учитывает снятие таймера Context и независимый таймер хранилища.

## Использование кода и возможности очистки

Полностью неиспользуемых исходных файлов внутри `src/process/` не обнаружено. Проверка TypeScript с `--noUnusedLocals --noUnusedParameters` прошла до изменения TTL. Она проверяет локальные объявления, а внешние потребители дополнительно проверены поиском по `src`.

- `commands.reportCryptoError` вызывался только тестами. По последующему запросу пользователя команда и её реализация удалены. Тесты подставляют ошибки в поиск сертификатов и создание подписи; реальные ошибки обрабатываются внутри соответствующего сценария.
- Публичный `commands.submitSignature` использовался только тестами. По последующему запросу пользователя он убран из Context; сама функция осталась внутренней частью `submitSelectedCertificate`. Сценарии проверяются через `submitCheck`/`submitSigning`, а синтетические результаты и отложенные подписи задаются моками в тестах.
- `commands.retry` не вызывался интерфейсом. По последующему запросу пользователя команда удалена, описание задачи 02 обновлено. Тесты явного повтора используют настоящий обработчик кнопки STATUS/BACK: при отсутствии рабочего экрана он запускает START и сбрасывает бюджет 401.
- `workplaceCertificates` записывается, но UI его не читает. R-13 прямо требует сохранить сертификаты ручной проверки в памяти; удалять поле только по отсутствию потребителя нельзя. CHECK/SIGNING правильно получают отдельную актуальную выборку.
- `serverProcess`, `errorKey`, навигационные `from`, `target`, `backTo` сейчас не читаются рабочими экранами. Это предусмотренные контрактом состояния/навигации данные; они не признаны ошибками аудита.
- Чтение версии 1 кэша SETTING используется для совместимости с ранее сохранённой записью и покрыто тестом.

До исправления: `npm test` — 248/248; typecheck, lint, build прошли. HTTP-тестам потребовался доступ к localhost вне песочницы: первоначальный EACCES не был ошибкой приложения. Четыре временные диагностические пробы подтвердили описанные выше наблюдения; временный файл удалён.

После исправления: результаты итогового набора записаны в PROGRESS.md. Prettier для изменённых исходников проходит. Полная проверка каталога `src/process` обнаружила прежние нарушения форматирования в `NavigationContext.tsx` и `ProcessErrorBoundary.tsx`; эти файлы не изменялись. Сборка сообщает о direct eval внутри зависимости КриптоПро.
