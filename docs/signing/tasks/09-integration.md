# 09. Сквозная проверка, итоговая очистка и передача

Статус: не начата. Зависимости: 01–08. Результат — подтверждённая готовность согласованного объёма, а не только успешная сборка.

## Вход

Весь пакет, особенно [ACCEPTANCE.md](../ACCEPTANCE.md), [DECISIONS.md](../DECISIONS.md) и [PROGRESS.md](../PROGRESS.md).

## Работа

1. Пройти все AC-* и сквозные сценарии матрицы. Для каждого результата указать доказательство: тест, скриншот, протокол ручной проверки или явный блокер.
2. Проверить реальные Browser Plug-in/CSP и тестовые сертификаты 256/512, согласованный TSP/profile, отсоединённые подписи MVP для одного и нескольких документов и принятие полного комплекта бэкендом. Не использовать реальные клиентские документы в фикстурах.
3. В браузере с тестовым бэкендом проверить HTTP 303/task, 401/restart с максимум одним автоматическим START и доступность X-Request-Id. Если окружения нет, отдельно обозначить непроверенную интеграцию; моки её не заменяют.
4. Проверить гонки: двойной клик, новая заявка при активном запросе, BACK из ошибки, unmount, поздний poll/плагин, повтор HTTP после созданной подписи, отсутствие накопленных таймеров/object URL.
5. Проверить интерфейс на заданных ширинах, клавиатуру, длинные тексты, выбор сертификата, просмотр/скачивание и все STATUS. Удалить из production фиктивные успешные ответы, переключатели экранов и демонстрационный счётчик.
6. Повторно проверить очистку CryptoPro: нет неиспользуемых генерации/установки, копий cades_api, старого LESS/UI, лишних экспортов и зависимостей, добавленных промежуточной работой. Сохранять код только при реальном использовании.
7. Сверить документацию с реализацией: README с запуском/ограничениями, Context/API/CryptoPro/UI, решения Q-*, статус задач. Примеры должны соответствовать актуальным схемам.

8. Проверить AC-18/23/29: отказ для режимов вне MVP, выполнение `accent` по таймеру ровно один раз и сохранение `session`/`token` с очисткой при 401 или смене заявки.

## Проверки

`npm test`, `npm run typecheck`, `npm run lint`, `npm run build`; форматирование затронутых файлов. Если общий format:check показывает старые проблемы, указать их отдельно и не форматировать весь проект без необходимости. Автотесты покрывают значимое поведение; не добавлять тесты ради повторения структуры компонентов.

## Приёмка и ограничения

- AC-01–AC-29 закрыты для всего согласованного объёма.
- Изменение объёма подтверждено явным решением владельца, а не отсутствием реализации сложного режима.
- Все Q-*, влияющие на поставляемый сценарий, решены и перенесены в спецификации; прочие указаны как ограничения с владельцем.
- Нет утверждений об успешной реальной интеграции на основании моков.
- Реальные подписи, сертификаты и персональные реквизиты не попали в фикстуры/логи/документацию.

## Передача

Итоговый отчёт: реализованный объём, изменённые файлы, команды и результаты, проверенные окружения, непройденные сценарии и следующий необходимый шаг. Обновить PROGRESS. Если обязательный критерий не закрыт, указать фактическое частичное состояние вместо «всё готово».
